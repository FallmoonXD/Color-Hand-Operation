# OHO+ reference audit and independent implementation boundary

Reference: One Hand Operation+ 9.3.13.0, the captured Samsung profile, and the accepted test36 ColorOS appearance. The machine-readable inventory is `oho-feature-matrix.json`: 73 official action identities (including none), cross-checked against gesture_action_type_arr_values, and 24 behavior groups. Status means implementation evidence, not a claim of full equivalence.

## Architecture

The new APK must compile from ordinary Android source. It must not load gulugulu classes, patch smali, depend on an installed gulugulu package, or require apktool to build. Existing independently authored material and panel Java can be migrated. Device-specific commands belong behind an action/OS adapter; gesture classification must never contain shell commands.

Use independent ownership for gesture recognition, gesture presentation, action dispatch, overlay presentation, system adapters, and versioned settings. A gesture publishes one immutable start/end anchor when it dispatches. Native panels consume that anchor rather than a cached previous trigger. Long and short triggers must share an explicit state machine, preventing a short action after a long one.

`ActionExecutor.execute(service, id, anchor)` is the new stable action contract. It implements 60 selectable entries plus `app:<component>`, legacy `shortcut:<intentURI>`, and real `launcher_shortcut:1:<user>:<base64url-package>:<base64url-id>` entries. Commands run off the main thread with timeouts and explicit errors. All root helpers execute the new APK's own classes. Notification/quick settings, navigation, screenshot, lock and split use accessibility first. ColorOS one-handed mode, sidebar and recording use separate verified/adaptable OEM routes. No Samsung package name is substituted with a vaguely similar action.

## Source-derived behavior

OHO stores three directions and short/long actions independently per edge. Captured defaults used here are left straight short=recents, right straight short=back, both diagonal up/down=volume up/down, left straight long=one-handed mode, right straight long=edge panel, both long up=widgets, both long down=quick tools.

`MyGtsCellProvider.java` records separate short and long quick-action switches, defaults 0 and 1. `long_swipe_time` is multiplied by 50 ms (`a6/c.java`), with captured value6, therefore300 ms. Source w5/b.a classifies radial travel with hypot(dx,dy). Source b6/a schedules the remaining long timer from DOWN time, not a stationary dwell after crossing the long-distance threshold. On release, a long-distance classified gesture executes immediately even if the timer has not expired. The captured gesture angle slopes are3.732, .466, -1 and -3.732. Test36's accepted device-scaled travel thresholds are138 and306 pixels; these are not universal Android dp constants.

Handle behavior includes app exclusions, lock/home/notification-panel hiding, keyboard adaptation, separate landscape geometry, extra handles and cover-display settings. The regular two handles alone do not exhaust OHO functionality.

Quick tools allow12 configured entries, confirmed in `settings/quicktools/e.java`. Instant commands and stateful toggles have different highlighting semantics. Overlay focus, brightness raw range, volume long-press repeat, root denial and outside-touch dismissal are behavioral acceptance criteria.

Widgets require real provider binding/configuration, view-size reporting, provider updates, pages, continuous scrolling, sizing, edit and delete flows. **AppWidget IDs are owned by host UID: copying old IDs into the independently packaged APK cannot migrate live widgets.** Existing records can identify providers and dimensions, but new host bindings are required.

## Explicit remaining equivalence gaps

The current action implementation is broad but not a complete OHO clone. Quick launcher has a versioned layout with legacy favorites migration, persistent app/action entries, named folders, grouping/rename/delete, pages, three fixed rows, 3–5 columns, add/remove/reorder, installed icons, swipe paging, hover-release selection and an optional first page of real recent tasks. On-device tests verified creating a folder, adding the Back action, moving it into that folder and opening the folder. A real dynamic/pinned/manifest Android shortcut picker is now implemented for the current user, including other launchers' pinned items. An SDK37 read-only query returned four enabled Alipay shortcuts and publisher icons; end-to-end picker/launch validation is pending. Legacy CREATE_SHORTCUT configuration and work-profile selection remain gaps.

Task switcher reads real task IDs from a root ActivityTaskManager bridge, restores exact tasks and supports 5/10/20/30 item limits. On-device tests verified five real OnePlus recent tasks and restoration of the exact Settings task. Existing system task snapshot previews are now implemented with protected-buffer/theme-placeholder exclusion, bounded memory and cancellation; the SDK37 bridge returned five145x320 real task previews and UI acceptance is pending. Samsung multiwindow operations remain gaps. Per-app keyboard shortcuts support named 1–4-key combinations with editing/reordering and JSON persistence; device tests verified CTRL+A in Android Settings search by replacing the entire existing field through subsequent input. Other applications and combinations still require coverage. Virtual touchpad and floating navigation are independently implemented; device tests verified one actual pointer click, navigation Home, and persistence of the horizontal/vertical arrangement. Configurable touchpad speed0.5..3.0 and ordered1..5 navigation actions/40..76dp sizing are now implemented; their new settings await runtime regression. These spot checks do not imply exhaustive interaction coverage.

Native ColorOS side panel now uses `content call --uri content://com.coloros.sidebar --method OVOICE_OPEN_FLOATBAR_ACTION`. The decompiled SideBarProvider delegates to EdgePanelController.openSmartSideBarAction; device tests verified a complete sidebar on the phone. This replaces the synthetic swipe that conflicted with an ongoing long gesture. Its null provider result is normal, not an error. ColorOS one-handed mode was also exercised successfully. Independent screen-free-move and fullscreen magnification control overlays are now implemented; screen-free-move device acceptance is pending; device tests verified magnifier pan,2.5x and close. Additional handle/context settings are being covered separately. Android recents alone is not declared OHO task-switcher parity.

Samsung Wallet, Modes/Routines, AI/Smart Select, Game Booster, Samsung pop-up/multiwindow control, privacy display, S Pen and taskbar integrations depend on Samsung services. A verified ColorOS counterpart can replace the service contract while keeping the user-visible function; otherwise the feature stays explicitly unavailable. Hotspot and eye-comfort currently have **settings-entry alternatives only**, not equivalent direct toggles.

Native system icon reuse includes some generic symbols: timeout clock, close X and volume chevrons. Notification uses FloatAssistant's actual notification-center action icon, not the ringer bell. Native playback glyphs are used, but additional live playback/route-state tracking is a separate feature from resource replacement.

## Acceptance order

1. Compile independently, prove no gulugulu runtime dependency, launch/configure accessibility.
2. Exercise all twelve captured profile gestures, cancellation, long hold and rebound on both edges.
3. Verify tools and volume without foreground playback interruption; compare geometry/material/entrance on several backgrounds.
4. Rebind real widgets under the new UID, verify page operations, provider interaction, crop and updates.
5. Exercise process death, recent-task removal, rotation, keyboard, excluded app, sleep/wake and reboot.
6. Resolve each feature-matrix gap before describing the project as complete OHO+ parity.

The user explicitly prefers the fixed original OHO gesture style; the removed animation-style editor should not be reintroduced merely because OHO offers style choices.

Native magnification is offered explicitly as “系统屏幕放大”: Android Accessibility MagnificationController toggles 2× full-screen zoom at the gesture endpoint and resets on the next invocation. It requires declared canControlMagnification. OHO n5/a.w actually invokes IWindowManager.changeDisplayScale(MagnificationSpec); y5/j combines fullscreen 2x scaling with a small gesture-control window, not a custom screenshot lens. The new screen_magnifier action uses an independently authored movable control panel; its system API differs from Samsung's private display transform. Root confirmed dumpsys changed from activated=true/scale=2 to activated=false/scale=1. The system service may reject requests; rejection is surfaced.

Configuration validators are available before import mutation: LauncherLayout.validatePreferences checks version2/folders/entry types/references/duplicate keys/numeric fields and legacy favorites; KeyboardShortcutsOverlay.validatePreferences checks per-app namespaces and validated1–4key chords. Root migration owns the cross-file transaction.

Final source review added ownership and dismissal for nested launcher/task/keyboard dialogs, cancels pending recent-task reads when their panels close, suppresses delayed keyboard injection after foreground changes, and releases camera state callbacks on service disconnection. Normal selection panels retain FLAG_NOT_FOCUSABLE; only actual text editors request keyboard focus. This prevents accidental focus transfer by design, but does not itself prove that every third-party media application will keep playing. Root command handling checks both exit status and Android error output; nine host assertions cover zero-exit activity errors, service denial, valid task results and the native sidebar null response. Shell variables are fixed commands, validated numeric task/key IDs or properly quoted APK paths; arbitrary shortcut URI strings are passed through Intent parsing rather than a shell.

OHO+ 9.3.13 creates a button-sized, non-focusable mini-volume window in `r5.f.s`. Its touch listener in `y5.g` can receive an outside notification while the touched app receives the original gesture. It arms a 3-second timeout on show and a 1.5-second timeout on a button step or repeat. CHO follows the visible SystemUI volume window on ColorOS. These timeouts are the fallback when the system does not expose a recognizable window.

The standalone OHO+ screen-timeout picker (`r5.f.o`, `y5.p`) uses a narrow window and dismisses on an outside notification. In CHO this applies to the gesture action. The picker inside quick tools remains a modal child.

The OHO+ quick tools (`r5.f.c`), widgets (`r5.f`), quick launcher (`v5.a0`), task switcher (`l6.j`) and keyboard shortcut menu (`r5.f`) use screen-sized input windows around their content. CHO keeps taps outside those temporary panels in the topmost window. Its navigation rail and touchpad stay open for continued use of the foreground app.

Opening a temporary tool replaces the previous temporary tool through `ActionExecutor.preparePanel`. The navigation keys, touchpad and magnifier stay available across these switches. ToolsPanel's own toggles retain their panel. Reopening quick tools recreates it with the current trigger anchor. External launcher/task-switcher cleanup immediately cancels animations and dismisses owned windows; user outside-touch dismissal still animates. Root shell mutations share one worker queue to preserve submitted command order.

## Background recovery evidence

On this ColorOS build, ActivityManagerServiceExtImpl may reject service restarts before normal Android restart scheduling. OplusAppStartupManager's per-package auto-start policy applies even to a sticky foreground service. The verified fix was limited to `dev.edgeflow`: the native startup provider reported disabled with `canBeOpened=true`, accepted the single-package `setStartupState` update, and read back enabled. No global restart policy or accessibility enabled-service setting was rewritten for this fix.

GestureService explicitly starts itself and returns START_STICKY only while its own component remains in the enabled accessibility-service list; user disable stops the started-service lifetime. The secure global ACCESSIBILITY_ENABLED value is not used as authorization because it can drop when the last bound service crashes.

Two distinct device checks passed: removing the app's recent-task card preserved PID 31788 and subsequent tools functionality; after the package-level startup grant, `kill -9` of PID 21973 resulted in new PID 24369 and a working tools panel. The latter is process-death recovery, not an actual device reboot or an application force-stop test. Those scenarios remain separate acceptance items. `controls-validation.json` also records auto-brightness roundtrip, raw manual brightness, continuous volume changes, outside dismissal and retention of the foreground resumed Activity; it does not claim direct Bilibili playback validation.

## Real Android application shortcuts

ShortcutEntry stores canonical version/user/package/shortcut IDs without capturing launch Intents. ShortcutPicker queries the selected publisher, shows dynamic/pinned/manifest state, caches real publisher icons, and rejects disabled or missing entries. ShortcutBridge uses the independently built APK, drops a Root helper from UID0 to the real system UID1000, and calls ILauncherApps with the android package identity whose UID matches. It neither impersonates the default launcher nor changes/pins its shortcuts. The query requests flags 1035, including MATCH_PINNED_BY_ANY_LAUNCHER. On this SDK37 firmware startShortcut has an extra leading IBinder compared with the older seven-argument signature, so both exact forms are handled. Starts check the system boolean result and cannot silently fall back to opening an app.

Read-only phone evidence: four Alipay dynamic shortcuts and their bitmap icons were retrieved; see verification/shortcut-list-validation.json. Fourteen pure JVM assertions cover canonical identities, Unicode IDs, shell metacharacter round trips, invalid profiles/versions and size limits. Current-user picker/start device acceptance remains pending; CREATE_SHORTCUT wizard flows and work-profile selection are not implemented. The legacy shortcut:IntentUri format is retained but is not described as equivalent to publisher-managed shortcuts.

## Existing system task previews

TaskPreviewBridge reads only task IDs still present in the current user's recent-task list. On SDK37 it calls ITaskSnapshotManager.getTaskSnapshot with the declared low-resolution constant and never calls takeTaskSnapshot. Older supported forms explicitly pass takeSnapshotIfNeeded=false. Non-real system theme placeholders and hardware buffers marked protected are rejected; no secure-layer capture request exists. Previews are capped at320px on the longer side and transported directly to memory. TaskSwitcherOverlay releases bitmap references and cancels in-flight queries on refresh/close; root buffers close after each task. Screenshots are never persisted by the app. A read-only SDK37 bridge probe returned five145x320 task previews (8–46KB); only metadata was recorded in verification/task-preview-validation.json. Panel interaction/resource acceptance is pending.

Framework references used for the adapter design: [AOSP LauncherAppsService](https://android.googlesource.com/platform/frameworks/base.git/+/master/services/core/java/com/android/server/pm/LauncherAppsService.java), [AOSP TaskSnapshotController](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/services/core/java/com/android/server/wm/TaskSnapshotController.java), and [AOSP protected-content handling](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/services/core/java/com/android/server/wm/TaskSnapshotConvertUtil.java). Firmware SDK37 signatures were checked directly using the read-only ApiDump helper rather than assumed from those source revisions.

## Final inventory correction

The authoritative resource array contains73 gesture action IDs. Earlier icon/resource extraction incorrectly included s_key_media_* label names, close_all, and hide_handle; the matrix now uses key_media_*, the real handle_hide ID, and includes none, launch_memory and min_popup_view. Close-all text is an auxiliary panel resource, not an extra gesture action. Temporary handle hiding remains an unimplemented generic OHO interaction; Samsung popup minimization and the Memory entry require device-specific adaptation. These are retained explicitly instead of folded into the completed action count.
