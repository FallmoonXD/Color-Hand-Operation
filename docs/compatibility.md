# ColorOS 兼容范围

当前已测试的组合是 OnePlus PKR110、ColorOS 17 / Android 17、Root、主用户。Android 13 是清单中的安装下限，其他机型或系统版本尚未通过完整实机验收。

## 可以测试的路径

无障碍负责边缘手势、返回/最近任务等基础动作。工具面板、小组件和设置页使用应用自身代码。ColorOS 设置资源、颜色、字体及原生材质存在时会被读取；系统版本、主题和字号可能改变最终外观。

原生材质依赖 `com.oplus.blur` 与匹配的隐藏接口。缺少服务、Root 被拒绝或绑定超时后，本进程使用回退材质，不再持续请求授权；重新启动应用可重新探测。成功连接后的异常恢复最多两次。当前设备已经验证正常原生绑定和后续帧捕获。

亮度不再内置某台手机的范围。优先读取系统范围、OplusPowerManager 或明确的系统属性；无有效范围时禁用滑条。只有系统明确支持 Oplus 多位亮度时，才使用其 raw `screen_auto_brightness_adj` 语义。其他固件仍需验证显示百分比与实际亮度的对应。

## 需要分别验证的功能

- 单手模式、系统侧边栏、录屏、任务快照、部分系统开关及窗口变换依赖 OEM 接口。
- 自动启动、后台清理策略与 Root 管理器行为由系统控制，不能以一次成功启动代替重启或长时间验证。
- 折叠屏、外屏、平板、其他密度/横屏配置、工作资料及副用户尚未完整测试。
- 第三方小组件由提供应用绘制；配置 Activity 与权限提示仍由各自应用负责。

可选 `tools/keepalive.sh` 只对已记录的 PKR110 完整固件指纹执行 Athena 写入，其他固件在写入前退出。普通安装不会自动部署该脚本。`tools/deploy.py` 面向主用户开发调试，使用系统界面授权更适合普通安装。

## 反馈

请在 Issue 中提供机型、ColorOS/Android 版本、Root 管理器、出问题的具体功能和复现步骤。日志只保留相关报错；移除账号、令牌、序列号、应用私有内容。不要直接提交完整配置导出或个人小组件截图。
