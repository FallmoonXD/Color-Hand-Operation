# OHO 菜单与手势箭头修正：实机记录

2026-11-05，一加 PKR110 / ColorOS 17。安装版本 **0.2.0-oho-ui（versionCode 2）**，包名 `dev.edgeflow`。

## 修正依据与结果

主菜单原来把工具目录直接平铺，手势波形还额外绘制动作文字并替换部分箭头，偏离用户要求。本次按用户提供的 OHO+ 9.3.13.0 APK 的布局和 Activity 组织设置页，保留 ColorOS 的卡片、颜色、字体、开关和已确认浮层材质。

- 首页：总开关、说明、上下排列的左右触钮、添加/移除、高级设置、手势设置及条件性触控区域调节。
- 触钮页：三个短滑方向、带真实开关的三个长滑方向、对齐触钮及条件性几何设置。长滑方向图标只旋转箭头，不再连背景一起旋转。
- 功能配置：从动作选择器右侧齿轮进入参数页，返回后回到原动作选择器；参数页与浮层预览分开。
- 手势波形：删除绘制动作文字与动作图标替换，使用原 APK `ic_arrow_forward` 的矢量路径。六方向旋转正确，曲线继续使用不透明纯黑，尺寸与回弹参数未变。

原版首页证据来自 XML 与 Activity，本机没有可确认的 OHO 首页截图。因此这里验证的是源码支持的结构和一加实际显示，没有做三星首页的逐像素对照。详细依据见 [结构审计](oho-settings-layout-audit.md)。

初次自动化检查因快速惯性滚动跳过列表齿轮而失败；减小测试滚动距离并按目标位置调整方向后，完整导航验证通过。这是测试脚本修正，不作为应用故障或成功结果隐藏。

方向图标背景的最后一处视觉修正后再次构建并覆盖安装，针对最终 APK 复查了触钮页、色板、六方向手势、快速工具、小组件和配置保留。七路导航的完整回归来自该视觉修正前同一 0.2.0 功能实现，最后修正只分离图标和背景的旋转。

机器记录：`verification/oho-ui-validation.json`；过程测试为 `tools/verify_oho_ui.py`、`tools/verify_oho_final.py`。本地 Java 检查为 **68 个手势状态断言、51 个手柄断言、111 个配置/几何断言**；Gradle `assembleDebug --offline` 成功。
