## 0.3.22 恢复原版退场

EdgeFlow 0.1.0 的本地源码包和 CHO 0.3.15、0.3.19 的 `ColorMotion.exit` 都以 250 ms、`spring(.47,0)` 收回居中浮窗。弹簧控制窗口透明度，视图同时缩小到 88% 并下移 12 dp。本版直接恢复这套参数，保留先让当前窗口处理返回、退场完成后再执行快速工具动作的修复。

PKR110 上点快速工具窗外，从九成到一成的画面对比度，0.3.19 录得 52 ms，恢复后录得 54 ms。可用 `python tools/verify_panel_exit.py --back-handle right --output verification/original-exit` 复测。脚本分别核对录屏中的可见变化和快速工具窗口从请求关闭到移除的完整时长。

## 0.3.21 浮窗收回速度

0.3.20 的居中面板退场偏慢，已撤下公开安装包。快速工具等居中浮窗的完整退场改为 150 ms。入场途中关闭时，根据当前已显示的比例缩短退场。OHO+ 9.3.13 的快速工具在 `u5.i.b` 用 250 ms 将面板缩至零并淡出，`r5.e.f` 使用加速插值。CHO 的面板仅轻微缩小，150 ms 是为这种表现选择的时长。

录屏回归同时检查过快和过慢。对居中面板，正常动画速度下从九成到一成的可见变化应在 65–130 ms，有至少四个中间帧。这是 CHO 在 PKR110 上的回归范围。用 `tools/verify_panel_exit.py --output verification/panel-exit-speed` 可以单独保留本次结果。

一加上点快速工具窗外，0.3.20 公开包录得 177 ms，本版候选包录得 107 ms、9 个中间帧。小组件和任务切换器点窗外分别为 106 和 109 ms。

## 0.3.20 浮窗退场

0.3.19 的普通玻璃面板用了 250 ms 的动画，但弹簧曲线在最初几帧就把大部分可见变化走完了。PKR110 以正常动画速度录屏，点窗外时，快速工具和小组件从九成到一成的画面对比度都只用约 50 ms。居中面板改用项目已有的 COUI 底部弹层退场曲线后，同样点快速工具窗外测得 179 ms。另外，用 CHO 返回手势关闭快速启动和任务切换器时，旧代码在系统收到返回前就强制移除了面板。录屏中没有中间帧。

实机复测用 `python tools/verify_panel_exit.py`。已将短直滑设为返回时，可以加 `--back-handle left` 或 `--back-handle right`。脚本测量录屏中的中间帧、可见变化的时长，并确认关闭后仍在原设置页。窗外点击是否穿透由 `tools/verify_panel_input.py` 单独检查。录屏和测量结果在本地 `verification/panel-exit/`。

这台一加上，CHO 返回手势关闭快速启动和任务切换器分别测到 13、16 个中间帧。键盘快捷方式用的是向下滑出的底部弹层，另用录屏核对了位移。

### 手势、工具与界面

快速工具的扬声器可切换媒体静音，音量为零时也能从按钮恢复声音。播放键读取本机实际播放活动，随播放、暂停和外部控制更新图标。播放器按键通过 Android 的媒体键分发。实机回归可运行 `tools/verify_quick_media.py`，会临时安装一个播放静音音轨的测试播放器。截图和发布校验在 `verification/media-release/`。

横屏触钮、试划预览和手势箭头贴物理左右边缘。横向导航栏显隐不移动触区；挖孔只排除与触钮相交的部分。横屏宽度默认沿用当前触钮的宽度，也可以在「触钮范围」按侧设置。PKR110 实机在距边缘 10dp 起手，8dp 宽时底下的按钮收到点击，12dp 宽时 CHO 收到内滑。三键导航下，从隐藏导航栏所在一侧滑入可以同时露出导航栏并触发 CHO。记录在 `verification/landscape-edge/`。

设置页工具栏从系统设置读取 `coui_back_arrow`，按 24dp 绘制。虚拟导航键使用 SystemUI 的返回、主屏幕和最近任务图形。图标按笔画重心居中，统一显示为白色，缺少系统资源时使用随包矢量。PKR110 的轮廓对照可运行 `tools/verify_navigation_glyphs.py`。本机前后对照、上下限位与横屏五键截图保存在 `verification/virtual-nav-refinement/`。

手势试划复用真实触钮和识别定时器。打开试划页后，命中结果交给页面显示，手势动作不会执行。设置页可按应用覆盖单个位置；显式「无」与继承全局分别存储。服务在按下时读取焦点应用，派发前重新核对。应用例外优先。快速启动文件夹以稳定 ID 绑定，改名后仍可滑入；删除后保留可重新选择的失效绑定。导入、导出支持这些新映射。

快速启动最近页按应用展示最多六个入口，「全部任务」打开按任务 ID 排列的完整列表。两处共享查询、短时结果和失败处理。系统页面动作集中在同一入口，仍可直接搜索。虚拟导航键沿触发侧竖排。参照 OHO+ 9.3.13 的浮动导航按钮，窗口以手势起点高度居中，在两端保留导航栏空间，并避开当前可见的触钮和屏幕缺口。关闭键和首个动作之间留 16dp，动作之间留 12dp。两侧预览在导航键设置页。试划、前台切换、文件夹改名与滑选、任务去重及边缘按钮的本机记录在 `verification/gesture-features/`。

玻璃材质已移除面板和控件中央的矩形高光。浮窗给投影留出额外的绘制空间。在 PKR110 的快速工具上，底部阴影现在能连续淡到下层页面的底色。导航键的滑条控制点击范围，玻璃圆钮从各边内收 6dp。整列共用一层磨砂底，间隙也能遮住页面文字和图标。圆钮采用快速工具的控件高光。实机对照在本地 `verification/glass-edge/`。

虚拟导航键沿起手侧展开并收回，使用系统侧边音量条的 COUI 弹簧。PKR110 上，导航键与快速工具圆钮在浅灰、深灰和蓝色背景下的底部高光都在向内第 3 个像素达到峰值。虚拟触控板的标题按整窗居中，底板、触摸区和按键采用快速工具的明暗分层。任务切换器在标题、滚动区和底部入口之间各留 8dp。触控板和任务切换器的布局回归见 `tools/verify_overlay_layout.py`，实机对照在 `verification/overlay-polish/`。

快速工具、小组件、快速启动、任务切换器和键盘快捷方式接收从窗外开始的触摸，抬手收起最上层，底下的应用收不到这次点击。虚拟导航键、触控板和放大镜把窗外触摸留给前台应用，切换应用或临时打开其他工具时可以继续保留。导航键旋转后回到原来一侧，触控板保留相对光标位置和滚动模式。息屏、关闭手势总开关或退出服务会收起浮窗。放大镜跟随系统当前倍率。实机回归入口为 `tools/verify_panel_input.py`，两层测试页面的点击结果在 `verification/panel-input/`。

音量按钮空闲时与系统紧凑音量条一起收起。点按钮以外的屏幕、拖动系统音量滑条或展开完整混音面板，都会单独收起 CHO 按钮；原点击继续交给前台应用或 SystemUI。按钮从当前位置向触发侧缩小、淡出，动画结束后才移除窗口。连续调音量会续期，无法识别系统音量窗口时按无障碍超时设置回退。回归入口为 `tools/verify_volume_window.py`，PKR110 的超时、窗外点击和展开录屏在 `verification/volume-button-exit/`。独立「屏幕超时」动作允许点击前台应用，快速工具里的二级时间列表只收起当前菜单。

音量胶囊、快速工具、小组件、导航键和其他玻璃面板共用系统侧边音量条的提亮强度。亮度随下层画面调整，沿实际轮廓过渡，控件内部不会出现另一块矩形。PKR110 浅色模式下，CHO 音量按钮和系统音量条在相同浅灰底上取样均为 `#C9CACB`。本地对照在 `verification/title-glass-match/`。

快速工具只在控件之间的底板叠加 9.4% 黑色。音量区、轨道和按钮继续取原来的玻璃亮度。「面板与工具 → 快速工具 → 一次性动作使用强调色」默认关闭，开启后截屏、锁屏等动作按钮跟随系统强调色。Wi-Fi 等开关仍按实际状态着色。

手势箭头按 OHO+ 9.3.13 的曲线样式定位。左右两侧都以当前触点为准，往上移三个箭头图标尺寸，靠近上下边缘时限位。PKR110 上从同一高度直滑，触点在 y=1450 px，修复前箭头中心在 y=1450 px，修复后左右两侧都在 y≈1219 px。手势判定和面板弹出位置继续使用原始触点。

快速工具和小组件由无障碍浮层接收返回，打开面板时底下的 Activity 保持 resumed。有二级菜单时，第一次返回只关菜单。PKR110 上用两层测试页面分别试了系统返回键、导航栏返回和 CHO 的返回手势，两种面板共六种组合，底下的第二页都保留。小组件的系统绑定和提供方配置仍由 Activity 接收结果，取消新增会释放新 ID，取消已有组件的配置会保留原 ID。实机对照与检查结果在本地 `verification/wave-back-20261107-133312/`。

关闭应用使用实时焦点窗口，Root 授权完成后再次确认，最后核对顶层任务、用户和锁屏状态。两种屏幕放大功能共用 API 33 兼容实现。旧浮点触钮透明度在编辑和备份时转换为整数百分比。亮度请求支持取消和超时，快捷键新名称限制为 256 字符，旧超长名称可以完整导出和恢复。

已在 PKR110 安装修复构建并测试快速工具/手势的有效与失效目标、系统放大、放大镜倍率、快捷键输入和亮度写入。23 组离线验证通过；API 33 使用缺少 API 34 激活方法的接口替身检查链接。设备测试助手会按单选行选择“返回”动作并等待读回，避免与页眉或系统返回键混淆。测试细节保存在本地 `verification/bugfix-ui-20261107-110400/`。

## 工程结构

这是独立 Android 工程。主要入口是 `MainActivity`、`GestureService`、`GestureRecognizer` 和 `ActionExecutor`；设置控件、主题、浮层材质及小组件在 `replica/`。

构建和运行不读取外部 `analysis/`，也不需要安装参考应用。改名称或外观时保留包名、配置格式和小组件 host ID，避免影响已有数据。公开版本使用 `X.Y.Z`，Release 标题使用 `Color Hand Operation X.Y.Z`。

## 构建与设备操作

JDK 21、Gradle wrapper 9.5.1、AGP 9.2.1、SDK platform 35 / build-tools 36.0.0。普通 APK 构建不需要 Python。图标生成工具使用 Pillow、resvg_py；旧矢量轮廓处理另需 skia-pathops。

ADB 只有一台已授权设备时自动选择，多台设备必须设置 `EDGEFLOW_SERIAL`。部署保留其他无障碍服务，旧视觉测试版迁移需要显式选项。

手机 UI 树使用独立 probe，避免普通 `uiautomator dump` 干扰无障碍服务。只读 probe 偶发被系统结束时可以重试；写入动作要先读回结果，再决定是否重试。测试前记录需要恢复的亮度模式、音量、配置和临时状态。

涉及实机 UI 时先读取当前亮度、充电保持唤醒和超时设置，保持已解锁屏幕直到实机步骤完成。结束后恢复临时修改的值，按当次情况息屏，避免长时间停留在静止画面。保留机主已设置的充电常亮和低亮度。

## 功能与兼容

亮度仅在读取到可信范围后允许调整。原生材质有服务检查、授权/绑定失败处理和有限重连。Athena 脚本只匹配已经记录的机型及完整固件。

此前在 PKR110 上测试过 2..4095 亮度范围、写入后恢复、快速工具和小组件原生材质、音量手势及配置保留。部署逻辑、亮度和材质恢复策略的离线检查分别为 24、49、15 项，具体对应 0.3.15 的记录。历史测试次数不累计成新版本回归结果。

其他机型和固件、无 Root、工作资料/副用户、折叠屏、跨签名升级及长期后台表现还需要测试。详细功能差异见[功能说明](feature-status.md)和[兼容说明](compatibility.md)。
