# 0.3.15 白灰图标与公开准备验收

2026-11-06，OnePlus PKR110、ColorOS 17、Android 17、Root，versionCode 18。

## 视觉依据

亲自查看了当前安装的 OPPO 视频、音乐、主题商店默认启动器图标，并用桌面截图确认实际显示为同一组图标。参考的是乳白/灰色分区、柔和内缘和薄亮边；本机主题缓存中另存的旧平面图标没有作为当前显示依据。

当前图标保留紫橙背景、原始手机与手的轮廓、渐隐箭头。彩色前景用中性白灰分开机身、屏幕和手，边缘高光只沿原有轮廓。通过原始前后手曲线的布尔并集得到一个连续可见手部，没有重画手指、增加掌心或袖口分段。

MD3 只有机身、填充屏幕、整只手三档深浅。原生 Android 绘制采样：机身 alpha163，屏幕86；拇指、后手、掌心、手腕及手臂均为255。大图、72px/44px预览、原生资源绘制及桌面图标都已目视检查。预览文件见 `design/icon-mask-preview.png`。

## 公开前修正

- ADB 部署取消个人序列号默认值，保留其他无障碍服务；固件专属 Athena 写入增加精确机型/固件条件。
- 亮度无可信范围时禁用写入；只有明确的 Oplus 多位亮度能力才写 raw 调整值。
- 原生材质检查服务与宿主用户；授权/绑定超时或首次失败后降级；成功连接后的异常恢复有上限。
- 公开源码不包含个人验证目录、完整 APK 分析、构建缓存、签名密钥或本机 SDK 路径。更新安装、兼容与接续文档，补第三方许可文本和素材来源说明。

## 结果

整包 `assembleDebug --offline` 通过；部署24项、亮度49项、原生恢复策略15项定向检查通过。待提交 Git 树单独导出后也完成了离线构建，没有读取工程外的分析目录；归档图标来源文件的哈希保持一致。

实机快速工具亮度滑条启用，范围2..4095；经 UI 调到raw1353后，`screen_brightness` 为1353、`screen_auto_brightness_adj` 为1353.0，随后恢复原自动亮度模式及调整值。自动模式恢复后当前亮度会随环境变化，因此不把 raw 瞬时变化当作恢复失败。

快速工具原生材质连接正常，捕获帧数从10增至131；小组件切换后仍连接，帧数138。音量手势通过，音量已恢复。四个偏好空间与测试前一致，无障碍服务仍启用。

安装 APK 与构建 SHA-256 一致：`33464570e27b4fa2feb99b33c1da94499c02dbfec65443a34c74852fd7c0d185`。桌面图标可正常启动应用。最后关闭 USB 保持唤醒并息屏，读回 Dozing、mStayOn=false。

本轮未在其他 ColorOS 机型实际安装，跨机型状态仍是兼容测试阶段。
