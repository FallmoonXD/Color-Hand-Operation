# 小组件接入检查

2026-11-11，在一加 PKR110 上检查了当前安装的全部 AppWidget 提供方。范围包括组件声明、CHO 的绑定与配置流程、尺寸与布局，以及按类型选择的实机样本。

| 检查项 | 结果 |
| --- | --- |
| 提供方声明 | 共 343 个入口，来自 46 个应用；29 个声明隐藏，314 个可列入普通添加列表 |
| 格数 | 258 个没有同时声明列数和行数；新建时结合提供方的最小尺寸和当前网格估算占位，替代原先固定的 4×2 |
| 配置页 | 可见入口中 6 个要求配置、4 个允许跳过配置。全部入口另有 1 个隐藏入口声明配置页 |
| 隐藏入口 | 使用真实测试提供方验证隐藏标记，普通提供方仍可添加。既有绑定按原记录保留 |
| 必需配置 | 取消后释放刚分配的 ID；完成后入页；回到 CHO 再开面板会带回未完成的配置页 |
| 可选配置 | 首次添加直接显示，已有实例可再次打开配置 |
| 非 4×4 布局 | 验证 2×2、5×6、6×5、恢复 4×4、取消编辑，以及 6 列下的组件交换 |
| 布局编辑状态 | 未应用的行列选择可跨横竖屏保留；横屏已补测滚动、拖动行数滑条以及取消后配置不变 |
| 实际内容 | 日历“今天”显示为 2×2；网易云音乐“私人漫游”显示为 4×2；世界时钟显示为 4×3，并加载城市列表 |
| 数据保留 | 实机回归结束后逐项核对 CHO 偏好文件与绑定 ID；临时组件和页面收回 |

元数据检查发现两个共性问题。CHO 原先给没有格数声明的组件一律分配 4×2，未考虑提供方的最小尺寸。配置页面进入后台后，面板入口又会因“配置进行中”而直接返回，没有带回那个页面。这两条已处理，相关逻辑不按应用名称区分。

灵感时钟、单条便签等依赖桌面或应用自己的添加流程。它们的普通 AppWidget 入口标记为隐藏，专用接入仍待完成。其他提供方是否需要登录、联网、应用内授权或业务初始化，也需要在实际状态下核对。

本轮没有逐个操作 343 个入口。账号选择、付费内容、工作资料、多用户、离线状态，以及长期后台更新仍待测试。渲染出视图不能单独证明提供方的每项功能都可用。后续遇到新故障，应继续检查同类接入流程和相同组件声明，而非只记录报错的应用名称。

原始清单、测试脚本、界面图和结果在本地 `verification/widget-grid/`。公开文档仅记录范围与结果，设备应用清单和截图留在本地。

## 固定内容尺寸与添加列表

有些提供方收到新尺寸后仍返回固定大小的 RemoteViews。本机支付宝的容器固定为 170dp 高，CHO 原先把它直接约束到约 147dp，导致外沿裁切。宿主现在在发现固定内容超出格位时重新测量并等比适配，参考桌面的子视图缩放路径；不以应用包名决定行为。普通自适应组件保持原布局，滚动及集合内容只检查视口，不把整份列表缩进格位。

固定尺寸测试提供方在 4×2、2×2 两种格位下，四角完整，八次角落点击均命中。自适应组件的尺寸与点击、集合组件显示以及整套编辑回归通过。实际抽测支付宝、日历月视图、世界时钟和网易云音乐 4×1；视图正常不代表账号数据或长期刷新全部通过。

日历月视图和世界时钟内部使用可滚动集合，已验证能滚到后续内容。屏幕边界处暂未显示的列表项目应通过滚动访问，不能将整个集合等比缩小来模拟“全部显示”。

添加列表沿用 COUI 底部弹层入退场，并按系统面板的 response 0.3、bounce 0 调整键盘避让。窗口本身保持边界，内部面板连续移动和缩放可用高度。检查包括开关键盘、连续反向切换、空结果、搜索词保留、键盘打开时取消／选择、横屏浮动键盘及关闭系统动画。原始录屏和结果在 `verification/widget-clip-ime/`。

CHO 的普通 AppWidget 与桌面卡片中心在可见内容上仍有差异。用户要求排除需要下载的推荐卡片后，再核对其本地数据来源与接口；此项明确留待后续，不计作此次裁切与输入法修复已完成的能力。

本次后续审计已整理到[小组件与桌面卡片数据链路审计](widget-card-data-audit.md)。结论是：普通 AppWidget 与桌面卡片分别由 `AppWidgetHost` 和 Pantanal／Seedling 卡片引擎管理；后者使用 `cardId`、`cardType`、`hostId` 及签名权限，不能用 CHO 当前的 AppWidget ID 代替。后续应先做同一提供方的语义数据对照，再考虑是否存在可授权的系统桥接。

## 桌面菜单与确认框

2026-11-11 继续沿桌面的 `FixedWidgetShortcutLoader` 和 `OplusBaseSystemShortcut` 核对菜单。桌面本身只读取 `oplus.appwidget.shortcuts` 中的 `common_settings`；CHO 没有遗漏同一 XML 中其他已支持的 style。主题卡片的编辑、替换和灵感时钟的设置则依赖 Launcher 的卡片记录及视图模型，不能仅靠 AppWidget 的声明补出来。这部分仍待接入。CHO 保留 Android 提供方声明的重新配置入口，尚未宣称所有菜单都与桌面一致。

移除确认必须核对实际视图。只看 `IconDelete` 的普通分支，会误以为桌面直接删除插件；实机添加测试提供方后确认，它被外层容器包装，转入 `LauncherSettingsUtils.showAreaWidgetDeleteConfirmPanel`，显示“要移除此插件吗？”和“移除插件不会删除应用内数据”。

CHO 的插件移除和整页移除现在共用桌面式底部确认框：读取已安装桌面的文字样式、间距、实色背景和圆角参数，确认按钮跟随强调色，不显示拖拽条。入退场沿用桌面 `coui_bottom_dialog_enter/exit` 的 250 ms 和对应曲线。无障碍窗口以实际可用屏幕定位，避开导航栏。

已验证三种取消路径均保留原布局、确认后只释放所选绑定，以及横屏整页确认的导航栏避让。新确认框退场录到 19 个中间帧。完整回归曾因旧菜单录屏只有 2 个有效中间帧而中断；单独三次复测均为 3 帧，原始失败和复测结果都保留。提供方设置、重新配置以及全部原偏好恢复另行验证通过。

其他确认框也已核对：快速启动删除文件夹采用桌面式确认；首页移除触钮／恢复默认、工具编辑放弃修改参照系统设置“重置应用偏好设置”。设置类按钮均用灰底，桌面类确认按钮用强调色，正文单行居中、多行左对齐。确认、取消、返回、窗外点击及大字体／深色／横屏测试记录在本地 `verification/widget-integration/`，前一批对照在 `verification/widget-menu-parity/`。

## 宿主补齐与实际限制

### 通用 AppWidget

- 按提供方的 `autoAdvanceViewId` 接管集合自动轮播，沿用桌面 20 秒间隔、多个组件错开 250 ms。关闭窗口、离开可见区域或卸载提供方时不继续轮播；重新挂载后恢复。模拟检查与真实 StackView 提供方均已验证。
- 添加列表枚举系统允许访问的用户资料，给工作资料入口加系统标记；绑定、授权、配置和旋转恢复传递同一个 `UserHandle`。当前一加只有一个资料，跨资料实机验证未完成。普通资料的绑定和配置回归通过。
- 工作资料组件的导出记录明确要求重新选择目标资料，迁移不会把同包名的个人资料应用当作原提供方。普通配置导入仍不复用旧 host ID。
- 提供方不可用时保留原格位并显示提示，长按可以移除。RemoteViews 加载失败显示错误提示，不再只有一块空白。取消不删除记录，卸载后的移除已实测；新版本提供方恢复同一绑定时会重新创建视图。

本轮完整编辑回归通过，翻页录屏确认新增、滑动、移除均有连续位置变化，固定底板的 RGB 通道波动为 0。错误布局测试、面板打开时卸载提供方、取消与删除占位均有实际提供方测试；原有绑定与偏好保持一致。离线检查分别为配置 364 项、交换 94 项、对话框 61 项、自动轮播 15 项。

### 不能直接当作普通小组件的入口

| 类型 | 已核实的调用方式 | 当前结果 |
| --- | --- | --- |
| 单条便签的旧 AppWidget | `NoteWidgetProvider` 读取便签进程的待添加笔记和内部 widgetId→笔记映射；尺寸 options 不接收笔记 ID。没有公开配置 Activity | 不能通过补一个标准配置 Intent 选择已有笔记；仍未接通 |
| 便签新卡片选择页 | `NoteSelectActivity` 要求 `com.oplus.permission.safe.ASSISTANT`，使用 cardId、cardType、hostId 识别 Seedling/RPK 卡片 | 该权限为 signature/privileged；实机检查 CHO 未获授。它不是旧 AppWidget 的配置页 |
| 便签编辑和数据组件 | 要求 `oppo.permission.OPPO_COMPONENT_SAFE` | 该权限为 signature；实机检查 CHO 未获授。系统应用挂载没有自动赋予它 |
| 灵感时钟 | 隐藏 receiver 不提供画面；`InspirationClockRepository.inflateInspirationClock` 依赖桌面进程内的 Launcher、InspirationClockInfo 与卡片资源 | 没有可供普通 AppWidgetHost 接收的 RemoteViews；仍未接通 |
| 主题／系统卡片 | 卡片服务检查 `com.oplus.permission.safe.ASSISTANT`；编辑、替换使用桌面记录 ID、卡片类型和桌面视图模型 | 不能用 CHO 的 widget ID 冒充桌面 itemInfoId。菜单的完整编辑／替换能力仍未接通 |

以上限制来自当前固件的 manifest、实际权限读回和对应调用路径，不代表其他固件也使用同一个接口。过滤隐藏入口只能避免错误添加，不能算作支持这些卡片。若以后增加桌面进程桥接，需要另行处理宿主生命周期、卡片数据隔离和系统版本适配；本轮没有改写桌面或便签的私有配置。

此轮另抽测了日历月视图／待办、世界时钟／普通时钟、全局搜索、网易云音乐 4×1、百度地图出行卡及便签公开待办入口。测试记录区分“已显示视图”和“业务可用”：例如便签可能显示迁移或权限提示，显示出提示不能记为已读到笔记。全局搜索的实际菜单为设置、移除插件，设置页跳转通过。尚未逐个操作全部提供方，也未替用户完成登录或应用内隐私确认。
